# 前端重构规划：AI 生图工作台科技感升级

## 目标

把 `timage` 和 `multimage` 从“表单堆叠式工具页”升级为更贴近 AI 生图场景的创作工作台：

- 更有科技感，但不要变成廉价霓虹或纯深蓝大屏。
- 操作更自然，用户从“想法/素材”到“生成/结果/历史”路径更短。
- 图片、文档、提示词、参数之间的关系更清楚。
- 生成过程要有“变化中”的反馈，而不是只有按钮 loading。
- 保留现有业务能力：登录、积分、上传、拖拽/粘贴、提示词优化、单图生成、图生图、批量分镜、历史图库。

## 设计方向

### 整体气质

关键词：`AI 创作舱`、`实时生成台`、`旅游视觉工作室`、`轻量科技感`。

视觉建议：

- 主背景：近黑灰或深墨绿灰，不要纯黑，不要大面积蓝紫渐变。
- 主色：青绿/湖蓝作为功能高亮，琥珀或暖金作为生成/额度/重点动作点缀。
- 辅助色：中性灰、冷白、浅雾蓝，用于文字层级和边框。
- 质感：半透明面板、细边框、微弱内发光、网格/扫描线可以少量使用。
- 避免：大面积渐变背景、漂浮圆球、营销页式 hero、过度卡片嵌套。

建议色板：

- `#08110f` 页面底色
- `#101b1d` 面板底色
- `#17272a` 次级面板
- `#2dd4bf` 主高亮
- `#38bdf8` 辅助高亮
- `#f6b44b` 生成动作/积分强调
- `#e7f7f4` 主文字
- `#8aa3a0` 辅助文字
- `rgba(255,255,255,0.08)` 边框

### 页面结构

两个页面统一成“工作台”结构，不再像普通后台表单。

#### 顶部

- 保留 Header，但压缩高度。
- 左侧：产品名 + 当前模式标签。
- 中间或右侧：登录状态、积分、充值入口。
- 右侧：历史作品入口或折叠按钮。

#### 主工作区

使用三栏或两栏响应式布局：

- 左栏：输入与素材区
  - 提示词/想法输入
  - 拖拽/粘贴上传区
  - 已上传素材缩略图
  - 文档状态

- 中栏：生成参数与智能辅助
  - 场景类型
  - 尺寸比例
  - 风格/季节/目的地参数
  - 智能优化结果

- 右栏：生成预览与结果
  - 当前生成状态
  - 本轮输出
  - 可点击预览、复制提示词、再次生成

移动端改为单列，顺序是：输入 → 参数 → 生成按钮 → 结果 → 历史。

## timage 改造规划

### 1. 输入区重构

当前 `prompt-area` 承担太多功能，建议拆成：

- `IdeaComposer`
  - 简单想法输入
  - 支持拖入/粘贴图片、TXT、PDF、DOCX
  - 输入框下方显示“已识别素材”：图片数量、文档名称、文本已追加

- `PromptEditor`
  - 专业提示词 textarea
  - 左上角放附件按钮
  - 右上角放“清空/复制/还原模板”等小图标按钮

- `AssetTray`
  - 6 张图片上限可视化：`3/6`
  - 图片缩略图支持删除、点击标记
  - 文档附件用文件 chip 显示，不参与图生图提交

### 2. 智能优化结果

优化结果不要只是卡片列表，改成“候选方案轨道”：

- 每个候选显示：
  - 风格名
  - 中文提示词摘要
  - 英文/专业提示词折叠预览
  - 选择状态
- 多选时底部生成按钮自动切换为“批量生成 N 张”。
- 单选时同步到 PromptEditor。

### 3. 生成状态

生成时右侧出现“生成舱”：

- 状态阶段：
  - 解析输入
  - 上传参考图
  - 调用生图模型
  - 上传成品
  - 写入作品库
- 用进度节点或脉冲线条展示，不需要假百分比。
- 当前 session 输出要占位，图片一出就填入，不等全部完成。

### 4. 参数区

把目的地、亮点、风格、季节做成紧凑控件：

- 目的地/亮点：普通输入框
- 风格/尺寸：下拉或 segmented control
- 类型选择：改成横向或网格小卡，减少长说明文字
- 每个类型只保留一句说明，详细说明放 tooltip 或 hover 展开

## multimage 改造规划

### 1. 模式切换

两个模式改成顶部 segmented control：

- 文案分镜
- 底图衍生

切换时只替换核心输入区，不让整个页面大幅跳动。

### 2. 文案/文档输入

输入区做成“智能投递区”：

- textarea 支持直接粘贴长文案。
- 拖入/粘贴 PDF、DOCX、TXT 后显示文档状态。
- 拖入/粘贴图片后自动切到“底图衍生”并显示底图。
- 明确状态文案：
  - `已加载文档：xxx.pdf`
  - `已设为基础参考图`
  - `TXT 内容已追加到文案`

### 3. 分镜结果

分镜结果从普通卡片改成“故事板时间线”：

- 每幕编号：Scene 01, Scene 02...
- 左侧短描述，右侧 prompt 摘要。
- 每张卡有：
  - 编辑 prompt
  - 单张重生成
  - 复制 prompt
- 正在生成时卡片中显示对应占位动画。

### 4. 批量结果

结果区以网格展示，但要保留分镜关系：

- 每张结果显示 Scene 编号和短描述。
- 鼠标 hover 出现：
  - 预览
  - 下载/打开原图
  - 复制 prompt
  - 重生成

## 组件拆分建议

目前 `pages/timage.js` 和 `pages/multimage.js` 文件偏大，建议 antigravity 在不改变 API 的前提下拆分：

- `components/image-workbench/AssetDropzone.js`
- `components/image-workbench/AssetTray.js`
- `components/image-workbench/PromptEditor.js`
- `components/image-workbench/GenerationStatus.js`
- `components/image-workbench/ResultGrid.js`
- `components/image-workbench/StoryboardTimeline.js`
- `components/image-workbench/SegmentedModeSwitch.js`

样式可以先用 `styled-jsx` 或 CSS Module，但两个页面要共享基础视觉变量。建议新增：

- `styles/workbench.module.css`

## 交互细节要求

- 所有上传入口都支持点击、拖入、粘贴。
- 拖入时投递区要有明显高亮状态。
- 超过 10MB 的图片自动压缩，不弹错误，除非压缩失败。
- 图片超过 6 张时提示“最多 6 张参考图”，并保留已导入的前 6 张。
- TXT 粘贴/拖入后追加到文本输入，而不是作为附件提交。
- PDF/DOCX 在 `multimage` 中作为文档分析数据；在 `timage` 中只作为参考附件展示，避免传给图生图接口。
- 生成按钮要始终说明消耗额度。
- 网络/API 错误要显示在结果区附近，不要只在页面顶部显示。
- 登录未完成时，生成按钮可以展示，但点击后引导登录。

## 验收标准

### 功能验收

- `timage`：
  - 可点击上传图片。
  - 可拖入图片。
  - 可从剪贴板粘贴图片。
  - 最多保留 6 张参考图片。
  - 10MB 以上图片会压缩后进入素材区。
  - TXT 会追加到 prompt。
  - PDF/DOCX 不会作为 `image` 字段提交到 `/api/timage/edit`。
  - 单图生成和多候选批量生成仍可用。

- `multimage`：
  - 文案输入框可粘贴普通文本。
  - 文案输入框可拖入/粘贴 TXT 并追加文本。
  - 文案输入框可拖入/粘贴 PDF/DOCX 并显示已加载文档。
  - 文案输入框可拖入/粘贴图片，并自动切到“底图衍生”。
  - 底图区域可点击/拖入/粘贴图片。
  - 分镜生成、批量生成、单张重生成仍可用。

### 视觉验收

- 页面首屏看起来像 AI 生图工作台，而不是普通后台表单。
- timage 和 multimage 视觉语言一致。
- 主操作按钮、辅助按钮、危险操作有清晰层级。
- 不出现明显文字溢出、按钮文字挤压、面板重叠。
- 移动端宽度下可以顺序完成核心流程。

### 技术验收

- `npm run build` 必须通过。
- 浏览器控制台无 React key、hydration、事件异常等明显错误。
- 不新增大型 UI 框架，除非明确说明收益。
- 不改动现有 API 返回结构，除非同步更新所有调用点。
- 保持已有登录、积分、历史图库逻辑可用。

## 我验收时会重点检查

1. 实际拖入/粘贴图片、TXT、PDF/DOCX 的行为是否符合预期。
2. 6 张图片上限和 10MB 自动压缩是否真实生效。
3. 图生图提交时是否只提交图片文件。
4. 两个页面是否有统一的科技感，而不是各做各的。
5. 生成过程是否有自然的中间状态反馈。
6. 移动端是否能完成完整流程。
7. `npm run build`、页面访问、核心 API 调用是否正常。
