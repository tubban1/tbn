# AI行程页面产品文档

## 功能目标

新增一个独立的AI行程规划页面，用于根据用户输入的目的地、天数、预算和偏好生成结构化旅行行程。

该页面应保持现有项目的简约工作台风格，并与 `timage` / `multimage` 的AI生图能力形成衔接。

## 功能列表

1. 行程输入 - 用户填写目的地、天数、人数、预算和旅行偏好
2. 行程生成 - 调用AI生成按天拆分的旅行计划
3. 行程展示 - 以 Day 1、Day 2 的形式展示每日安排
4. 行程复制 - 用户可以一键复制完整行程文本
5. 配图提示词 - 为每一天生成可用于生图的图片提示词
6. 生图衔接 - 支持将配图提示词复制到 `timage` 使用

## 页面结构

新增页面：

1. `/itinerary` - AI行程规划页面

页面建议采用三栏工作台结构：

1. 左栏：行程需求输入
2. 中栏：偏好和输出参数
3. 右栏：生成结果和配图提示词

移动端改为单列结构：

1. 输入需求
2. 输出参数
3. 生成按钮
4. 行程结果

## 输入字段

### 基础字段

| 字段 | 类型 | 必填 | 描述 |
|------|------|------|------|
| destination | string | 是 | 目的地，如“九寨沟”“京都”“川西” |
| days | number | 是 | 出行天数，建议范围 1-15 |
| people | number | 否 | 出行人数 |
| budget | string | 否 | 预算范围，如“经济”“舒适”“高端” |
| startDate | string | 否 | 出发日期 |

### 偏好字段

| 字段 | 类型 | 描述 |
|------|------|------|
| pace | string | 行程节奏：轻松、标准、紧凑 |
| travelType | string | 旅行类型：亲子、情侣、朋友、摄影、美食、深度游 |
| transport | string | 交通方式：自驾、公共交通、包车、不限 |
| interests | string | 用户补充兴趣点 |

## 输出结构

```json

  "summary": "适合第一次前往九寨沟的轻松路线。",

  ]

```

## API设计

新增接口：

1. `/api/itinerary/generate` - 生成行程

### 请求方式

`POST`

### 请求参数

```json
{
  "destination": "九寨沟",
  "days": 3,
  "people": 2,
  "budget": "舒适",
  "startDate": "2026-07-01",
  "pace": "轻松",
  "travelType": "摄影",
  "transport": "包车",
  "interests": "自然风光、当地美食、轻徒步"
}
```

### 返回参数

接口返回上文定义的行程JSON结构：

```json
{
  "success": true,
  "itinerary": {}
}
```

失败时：

```json
{
  "success": false,
  "error": "生成失败"
}
```

## AI提示词要求

后端接口应要求AI：

1. 只返回可解析JSON，不返回Markdown代码块
2. 每天至少包含上午、下午、晚上三个时间段
3. 每天包含一个适合AI生图的 `imagePrompt`
4. 输出内容使用中文
5. 行程安排要符合用户的天数、节奏和预算
6. 不要编造具体价格、航班号、酒店库存等实时信息

## 数据存储

第一版不强制入库。

如果需要保存历史，可新增 `itineraries` 表：

| 字段名 | 类型 | 描述 |
|--------|------|------|
| id | INT | 自增主键 |
| email | VARCHAR(255) | 用户邮箱 |
| title | VARCHAR(255) | 行程标题 |
| input_json | JSON | 用户输入 |
| result_json | JSON | AI生成结果 |
| created_at | DATETIME | 创建时间 |

## 前端交互要求

1. 用户填写基础信息后点击“生成行程”
2. 生成中显示明确的加载状态
3. 生成失败时在结果区显示错误信息
4. 生成成功后按天展示行程
5. 每一天显示主题、时间段、活动、说明、交通和提示
6. 每一天显示对应配图提示词
7. 支持复制完整行程
8. 支持复制单条配图提示词
9. 不要影响现有 `/timage` 和 `/multimage` 功能

## 视觉要求

页面保持简约风格，避免复杂装饰。

建议：

1. 使用 `styles/workbench.module.css` 的工作台基础风格
2. 保持深色背景和轻微科技感
3. 使用清晰的表单控件和结果卡片
4. 不做营销型Hero
5. 不使用大面积渐变背景
6. 移动端可正常完成完整流程

## 验收标准

### 功能验收

1. `/itinerary` 页面可以正常访问
2. 必填字段为空时不能提交
3. 点击生成后会调用 `/api/itinerary/generate`
4. AI返回JSON后能正确渲染
5. 每一天的行程内容完整展示
6. 完整行程可以复制
7. 单条配图提示词可以复制
8. API错误能显示给用户

### 技术验收

1. `npm run build` 通过
2. 不影响 `/timage` 页面
3. 不影响 `/multimage` 页面
4. 不新增大型UI框架
5. 不破坏现有登录、积分、历史作品逻辑

### 视觉验收

1. 页面风格与现有工作台一致
2. 结构清楚，输入区和结果区分明
3. 文本不溢出
4. 移动端布局可用
